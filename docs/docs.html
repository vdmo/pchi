PCHI 2.0 Protocol Documentation

PCHI (Peachy) v2.0 is a scene state protocol with embedded PIR (Prime Integer Relations) mathematical invariants that enables unprecedented coordination, verification, and intelligence in live creative software.

Why PCHI?

Live shows involve 10+ tools (Resolume, TouchDesigner, Ableton, lighting consoles, tracking systems) connected via 50+ custom OSC mappings. Scene coherence is maintained by convention, not mathematics. When something breaks, there's no way to prove the system is in a valid state.

Unlike traditional protocols like OSC, MIDI, or NDI, PCHI standardizes the "letter" (schema) while being transport-agnostic, and crucially, provides mathematical guarantees of scene coherence.

The Spiderweb Problem

14+ custom mappings requiring separate parsers, susceptible to silent failures.

The PCHI Solution

All tools communicate with a single Conductor using a unified, validated schema.

PIR Invariants

Every PCHI message carries PIR invariants that mathematically prove the scene is in equilibrium. Before any state change is applied, the PCHI Conductor validates these values.

  • Equilibrium Check: Uses the Prouhet-Thue-Morse sequence to verify mathematical balance (~62 µs per check).
  • Coherence Gap: Measures variance from the mean to detect state drift over time.
  • Curvature Signature: Approximates the second derivative for smoothness and transition safety.
"pirInvariants": {
  "equilibriumCheck": {
    "residual": 0.000000000001,
    "precision": 1e-12,
    "signSequence": [1, -1, -1, 1]
  },
  "coherenceGap": 0.0234,
  "curvatureSignature": "0.001234, -0.000567, 0.000890",
  "residual": 0.000000000001
}

Only-Lang Governance (Safe AI)

AI agents are powerful but dangerous in live environments. They can make decisions that break visual coherence or create unsafe conditions (e.g., blinding strobe lights). Only-Lang rules define mathematical boundaries for all behaviors. 

if kraken_tentacle.wobbliness > 0.8
then
    kraken_tentacle.wobbliness = 0.8
end

The PCHI Conductor enforces these rules before any generative or user-generated state change is applied. Safe suggestions pass; dangerous ones are clamped or rejected.

Message Schema

PCHI supports multiple message types based on the context of the broadcast:

  • scene_update: Object transforms (x, y, z) and custom data
  • control_parameter: Parameter changes for target systems (e.g. opacity, playback speed)
  • musical_context: BPM, beat count, kick/snare detection, song sections
  • artist_tracking: Real-time position and velocity tracking
  • heartbeat: System health and connection monitoring

PCHI Conductor

The PrimeSwarm Engine acts as the PCHI Conductor. It is a central Rust-based server that:

  1. Receives PCHI messages from all tools via UDP, TCP, WebSocket, or OSC.
  2. Validates PIR invariants instantly.
  3. Applies Only-Lang rules.
  4. Broadcasts the unified, coherent state to all receivers.
// Running the PCHI Conductor
#[tokio::main]
async fn main() {
    let conductor = PCHIConductor::new(1e-12);
    conductor.start_transport("0.0.0.0:8888").await.unwrap();
    conductor.load_rules("kraken-rules.only").await.unwrap();
    tokio::signal::ctrl_c().await.unwrap();
}

Integration Patterns

1. PCHI Hosts (Receivers)

Hosts receive PCHI messages and apply them to internal state (e.g., Unreal Engine, TouchDesigner). They listen to the Conductor's validated broadcast and automatically reject disequilibrium.

2. PCHI Clients (Senders)

Clients generate PCHI messages from their native state and broadcast them to the Conductor. They calculate their own PIR invariants prior to sending (e.g., Ableton Live, Resolume Arena, tracking hardware).

Resolume Bridge (Python / OSC)

This bridge listens to standard OSC messages from Resolume Arena, calculates the math, converts them to PCHI messages, and forwards them to the Conductor. 

pip install python-osc numpy
python resolume_pchi_bridge.py \
    --resolume-port 7000 \
    --pchi-host 127.0.0.1 \
    --pchi-port 8888 \
    --threshold 1e-12

OSC Mapping Example: /composition/layers/{layer_id}/video/opacity automatically maps to a PCHI control_parameter targeted at the layer.

TouchDesigner CHOP (Python)

A Python CHOP that connects to the PCHI Conductor via UDP. It dynamically creates channels based on incoming scene objects and musical data.

  • Equilibrium Channels: equilibrium, coherence_gap
  • Musical Channels: bpm, beat, kick, snare
  • Object Channels: {object_id}_x, _y, _z

Connect this CHOP to a Geometry COMP to mathematically drive object transforms in real-time.

Ableton Max Device

A Max for Live device that monitors Ableton Live's musical state (BPM, clip changes). It calculates PIR invariants directly from musical notes (pitch values mapped to Prouhet-Thue-Morse sequences) and emits a musical_context payload.
